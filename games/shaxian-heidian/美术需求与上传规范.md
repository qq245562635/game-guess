| 项目 | 要求 |
| --- | --- |
| 风格 | 《烟火像素 V2》：开罗式像素风，**斜 45° 等距视角**（2:1 菱形格），暖色，人物 Q 版 |
| 交图方式 | 场景精灵**按原生像素交**：图片尺寸就是像素数，一个像素就是一个点。不要放大，不要抗锯齿，不能有半透明像素 |

| 设施 | 一格的设施 **48×48**：**底部 24 行是占地菱形**（和地板一样大），物件站在菱形上往上长。高的（冰箱）**48×64**。两格的（卡座）**72×60** |
| 厨具模块 | 炉灶、蒸笼、汤锅是三个**单格模块**：同样高度、同样台面、同样柜门样式，并排放时台面连成一条（设定图“并排拼接”）。台面朝左前方 |

| 角色 | **24×32**，脚底贴底边、左右居中。每个角色 4 张：`_0` 斜前站立、`_1` 斜前迈步、`_b0` 斜后站立、`_b1` 斜后迈步。斜前是脸朝左下方；往右走由程序镜像 |

## 四、怎么上传

用 GitHub 网页上传就行，不需要装任何工具。需要先有这个仓库的写权限（没有的话找仓库主人在 Settings → Collaborators 里加你）。

1. 本地按目录整理好，文件名和清单完全一致（全小写、下划线）：
   ```
   characters/
     chef_0.png
     chef_1.png
   facilities/
     stove.png
   ```
2. 打开 https://github.com/qq245562635/game-guess/tree/main/games/shaxian-heidian/art
3. 右上角 **Add file → Upload files**。
4. 把整理好的**文件夹**（如 `characters`）直接拖进上传区。GitHub 会保留目录结构；同名文件会覆盖旧图，不用先删。
5. 页面底部填提交说明，格式：`美术：<内容>`，例如 `美术：P0 重做 灶台和上班族`。
6. 选 **Create a new branch for this commit and start a pull request**，分支名用 `art/日期`（例如 `art/1018`），点 **Propose changes**，再点 **Create pull request**。
7. 在群里告诉我 PR 链接。

`art/_rejected/` 里是退回的原图，只留作对照；重画的图上传到正常目录（`characters/`、`facilities/` 等），同名即可。

为什么走 PR 而不是直接传到 main：我验收通过后再合并，有问题可以在 PR 里逐张标出来，不会把坏图带进游戏。

## 六、验收流程

收到 PR 后我做三步：

1. **自动检查**：`node tools/check_art.js` 检查文件名、目录、尺寸、透明背景、空图、人物过小、主体贴边。
2. **人工看图**：拼成对照图，确认内容和文件名对得上、风格统一。
3. **进游戏看**：放进游戏截图，看手机尺寸下能不能认出来、走路动画会不会跳。

三步都过就合并上线；有问题我在 PR 里写明哪张、什么问题。验收记录写在 [art/README.md](art/README.md)。

## 七、出图方法与提示词（Codex / GPT）

**流程**：每张单独生成 → 用 `pixelize.js` 转成原生像素图 → 放大检查、手修几个像素 → 提交。

```
node tools/pixelize.js 下载的大图.png stove          # 输出到 art/facilities/stove.png
node tools/pixelize.js 下载的大图.png worker_b0      # 输出到 art/characters/worker_b0.png
```

`pixelize.js` 会：抠掉纯色背景 → 裁到主体 → 缩到清单尺寸（每个像素取那块区域的主色，不插值）→ 去掉半透明 → 合并噪点色、减到 24 色 → 角色和设施重描一圈深棕边 → 自动跑检查。
对 AI 的要求因此很简单：**纯色浅背景、主体有深色描边、一张只画一个东西**。没有描边的白色部分（比如厨师帽边缘）可能被当成背景抠掉。

**风格头（地板、墙、设施）**：每次附上设定图 V2 和 `art/_templates/` 里的同名占位图。

```
Isometric pixel art in the style of Kairosoft simulation games (like Cafeteria Nipponica), matching the attached "Yanhuo Pixel V2" style sheet: warm colors, 2:1 isometric projection viewed from the front at 45 degrees. Clean pixel art with hard edges, no anti-aliasing, no gradients, no noise. Dark brown outline (#2a1d16), light from the top-left: top faces brightest, left faces medium, right faces darkest. One single object on a plain flat light background, nothing else. No text, no letters, no watermark. Same footprint and position as the attached placeholder.
```

**风格头（角色）**

```
Chibi pixel art character in the style of Kairosoft simulation games, matching the attached "Yanhuo Pixel V2" style sheet, designed to be shrunk to 24x32 pixels: big head, simple shapes, bold dark brown outline (#2a1d16), flat colors, no gradients, no noise. Full body, one single character on a plain flat light background. No shadow, no text.
```
