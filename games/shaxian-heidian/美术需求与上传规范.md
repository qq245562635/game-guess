## 二、统一规格

| 项目 | 要求 |
| --- | --- |
| 风格 | 开罗游戏式像素风，3/4 俯视角，人物 2 头身 Q 版 |
| 像素格 | 场景、角色、道具按 **16×16 像素格**画，放大 4 倍交 **64×64**；每个像素是 4×4 的整块，不要抗锯齿、不要模糊 |
| UI 图标 | **12×12 像素格**放大 4 倍交 **48×48**；比场景简洁，粗描边，一个主色 |
| 背景 | 透明 PNG；只有地块（tiles）和宣传图（brand）是不透明的 |
| 构图 | 一张图只画一个东西，居中，脚底贴底边，四周留 4 像素空白；角色身体宽度至少占画面一半 |
| 描边与光源 | 1 像素深棕描边 `#2a1d16`，光源在左上 |
| 主色 | 沙县红 `#c0392b`、招牌黄 `#e8c35a`、黑店紫 `#a35ad6`、木色 `#9c6a3a`、不锈钢灰 `#b0b6bd` |
| 文字 | 图里**不要有任何文字**，文字由程序写（方便换皮和翻译）；`¥` 符号可以画 |
| 角色帧 | 每个角色两张：`_0` 站立、两脚并拢；`_1` 迈步，除了腿其他地方一模一样 |
| 版权 | 主角、房东不要照原剧演员的长相画，后期要换皮 |

## 四、怎么上传

用 GitHub 网页上传就行，不需要装任何工具。需要先有这个仓库的写权限（没有的话找仓库主人在 Settings → Collaborators 里加你）。

1. 本地按目录整理好，文件名和清单完全一致（全小写、下划线）：
   ```
   characters/
     chef_0.png
     chef_1.png
   facilities/
     stove.png
   ```
2. 打开 https://github.com/qq245562635/game-guess/tree/main/games/shaxian-heidian/art
3. 右上角 **Add file → Upload files**。
4. 把整理好的**文件夹**（如 `characters`）直接拖进上传区。GitHub 会保留目录结构；同名文件会覆盖旧图，不用先删。
5. 页面底部填提交说明，格式：`美术：<内容>`，例如 `美术：P0 重做 灶台和上班族`。
6. 选 **Create a new branch for this commit and start a pull request**，分支名用 `art/日期`（例如 `art/1018`），点 **Propose changes**，再点 **Create pull request**。
7. 在群里告诉我 PR 链接。

`art/_rejected/` 里是退回的原图，只留作对照；重画的图上传到正常目录（`characters/`、`facilities/` 等），同名即可。

为什么走 PR 而不是直接传到 main：我验收通过后再合并，有问题可以在 PR 里逐张标出来，不会把坏图带进游戏。

## 五、上传前自查

每张图上传前放大看一眼：

- [ ] 文件名和清单一致，放在对的目录里
- [ ] 尺寸对（64×64、48×48 等）
- [ ] 图里的内容就是文件名说的那个东西（第 1 批最大的问题）
- [ ] 透明背景，四周没有别的图的碎片
- [ ] 主体居中，角色身体宽度至少占画面一半
- [ ] 像素是整块的，没有糊边
- [ ] 角色 `_0` 和 `_1` 是同一个人，只有腿不一样
- [ ] 图里没有文字

## 六、验收流程

收到 PR 后我做三步：

1. **自动检查**：`node tools/check_art.js` 检查文件名、目录、尺寸、透明背景、空图、人物过小、主体贴边。
2. **人工看图**：拼成对照图，确认内容和文件名对得上、风格统一。
3. **进游戏看**：放进游戏截图，看手机尺寸下能不能认出来、走路动画会不会跳。

三步都过就合并上线；有问题我在 PR 里写明哪张、什么问题。验收记录写在 [art/README.md](art/README.md)。
