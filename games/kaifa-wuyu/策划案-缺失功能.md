# 开发物语 · 策划案：对照原作的缺失功能

> 对照《游戏发展国》原作，列出现在原型还没有的功能，排优先级，写清每项的玩法要点。
> 原作细节凭对原作的了解整理，标「待确认」的等看完视频再核对。
> 数值都是初版，先定玩法，后面再调。

---

## 0. 现状

已经有的：新企划书（渠道 / 类型 / 内容 / 开发方针）→ 方针 → 制作人 → 开发（40% 画面、75% 声音负责人）→ 渠道审核 → 媒体评分 → 每周销量；宣传；培训；职员一览；作品记录；游戏杂志；存档 / 重新开始；音乐音效。

占位中的菜单：委托开发、招聘、取得授权、公司数据。

## 1. 优先级总览

✅ = 已做进原型（2026-10-20）。P0 实现时的默认决定：上架费保持每次付；员工上限 4 人；名人堂门槛 36 分；暂不做对手作品。
P1 实现时的默认决定：年度大赏在每年 3 月第 4 周（游戏年度从 4 月开始），只评自家作品、按门槛颁奖，达不到就「从缺」；转职只花钱不用道具；黑客要求同一个人程序员、剧本作家都练满过（基础职业之间可以 1,000 金互转）；续作销量加成用宣传同款的衰减方式（+50%，每周 ×0.7）。

| 优先级 | 功能 | 为什么 |
|---|---|---|
| **P0** ✅ | 标题画面（新游戏 / 读取游戏 / 纪录） | 截图里有，游戏的入口 |
| **P0** ✅ | 公司命名、游戏命名 | 现在作品名是随机拼的，玩家没有代入感 |
| **P0** ✅ | 委托开发 | 原作前期主要收入，没它开局容易破产 |
| **P0** ✅ | 招聘 / 解雇 | 原作核心循环：赚钱 → 换更强的人 |
| **P1** ✅ | 员工经验、升级、转职 | 员工成长的主线，现在只有培训 |
| **P1** ✅ | 开发完成后的除 Bug 阶段 | 原作发售前可以继续修 Bug，决定要不要多花时间 |
| **P1** ✅ | 续作 | 原作重要玩法：好评作品出续作，粉丝和期待度继承 |
| **P1** ✅ | 年度游戏大奖 | 每年的高潮，配合杂志 |
| **P1** ✅ | 公司数据、纪录（名人堂） | 菜单占位要补上；纪录在标题画面就能看 |
| **P2** | 游戏展（每年一次） | 原作的宣传大事件，选展位大小 |
| **P2** | 办公室扩建 | 4 → 6 → 8 个座位，见 ASSETS.md 下一批 |
| **P2** | 渠道兴衰 / 签约（替代原作「取得授权」） | 本作把主机换成渠道，需要单独设计 |
| **P2** | 自建渠道（替代原作「自主开发主机」） | 后期目标 |
| **P2** | 20 年结局与评价 | 给一局游戏收尾 |

## 2. P0 功能

### 2.1 标题画面

照原作截图（`docs/ui/14-标题画面-原作参考.jpg`）：上方 Logo，中间竖排三个按钮，背景是办公室外的街景，底栏右下有一个键。

| 按钮 | 作用 |
|---|---|
| 新游戏 | 有存档时先确认「会覆盖现有存档」→ 公司命名 → 进入 1 年 4 月 |
| 读取游戏 | 读存档继续；没存档时按钮灰掉 |
| 纪录 | 看名人堂和历代最高成绩（见 3.5） |

- 原作右下是「返回地图」（开罗游戏合集的入口），我们不需要，改成空槽或「设置」（音乐 / 音效开关）。
- 存档先保持一个槽位，读取游戏直接进；以后再考虑多槽。
- 背景复用场景一的街景图，镜头拉远、不显示办公室内部 UI。

### 2.2 命名

- **公司命名**：新游戏时输入，默认「开发物语工作室」，最多 8 个字。显示在杂志、评分、纪录里。
- **游戏命名**：制作人选完之后、开工之前，弹输入框，默认值用现在的随机名（内容 + 后缀），玩家可以直接确定。续作默认「原名 2」。
- 输入用系统输入框即可，弹窗外观用通用弹窗。

### 2.3 委托开发

原作的委托：接外包活，不用自己出开发费，固定周期做完拿报酬，做得好有额外奖金。

- 入口：开发 → 委托开发。开发新作时不能接（同一时间只有一个项目）。
- 每月刷新 3 个委托，选一个接：

| 字段 | 说明 |
|---|---|
| 委托方 | 谐音公司名，例如「鹅厂外包部」「大字节」 |
| 内容 | 「做一个 H5 小游戏」「给 App 做活动页」「修 Bug」等 |
| 要求 | 一项能力达标：例如「画面 ≥ 40」，用全员能力合计判断 |
| 周期 | 2 ～ 6 周 |
| 报酬 | 600 ～ 5,000 金，达标多少决定奖金 |

- 进行中员工照常冒点数（但不累积到作品），信息栏显示「委托中 N 周」。
- 完成时秘书报告：「完成了！报酬 X 金」，超额完成加奖金和少量粉丝。
- 失败（要求没达标）：只拿一半报酬。
- 委托也给员工经验（见 3.1），是前期练人的方法。

### 2.4 招聘 / 解雇

原作：花钱登招聘广告 → 出现几位应聘者 → 看能力和工资 → 录用。座位满了要先解雇。

- 入口：职员 → 招聘。
- 招聘方式（越贵来的人越强）：

| 方式 | 费用 | 应聘者 |
|---|---|---|
| 在招聘网站发帖 | 500 金 | 3 人，能力一般 |
| 去高校宣讲 | 1,500 金 | 3 人，能力低、工资低（能力低时培训涨得快，没有单独的成长值） |
| 找猎头 | 5,000 金 | 2 人，能力高、工资高，2 年后解锁 |
| 粉丝推荐 | 免费 | 粉丝 5,000 以上偶尔出现，能力随机 |

- 应聘者卡片复用现有职员卡片（左右翻页），多显示「月薪」「成长」。
- 座位满了录用时，秘书问「要请谁离开？」→ 选一位解雇（无费用，秘书一句话）。
- 职员 → 职员一览 加「解雇」入口。
- 新员工外观从 6 种里随机；场景员工图要补到 6 套（ASSETS.md 里已经是 6 种外观）。

## 3. P1 功能

### 3.1 员工经验、升级、转职

- 开发、委托、负责人工作都给经验；经验满了升级（最高 5 级），每级本职能力 +3、其他 +1，工资上涨。
- 转职：等级 5 以后可以花钱换职业，保留部分能力。现有 4 个职业 + 后期职业：

| 职业 | 条件 | 特点 |
|---|---|---|
| 制作人 | 剧本作家 5 级 | 当制作人时全员点数 +10% |
| 硬件工程师 | 程序员 5 级 | 自建渠道需要（见 4.3） |
| 黑客（待定名） | 两个职业都到 5 级 | 四项能力都高，Bug 极少 |

- 原作转职要消耗道具（转职书）——待确认；我们先只用钱。

### 3.2 除 Bug 阶段

- 进度到 100% 时，如果还有 Bug，秘书问「还有 N 个 Bug，要继续修吗？」
  - 发售：Bug 照常扣分。
  - 继续修：每周按全员编程能力减少 Bug，进度条显示「除错中」，随时可以喊停发售。
- 信息栏 Bug 图标显示剩余数量（现在 Bug 是小数，要改成显示整数）。

### 3.3 续作

- 新企划书加一行「续作」：可选某部总分 ≥ 24 的已发售作品，类型和内容锁定为原作的。
- 加成：开发开始时期待度 = 原作粉丝的一部分；首周销量 +30%。
- 惩罚：同系列连续出，评分里「创新」打折（第 2 作 ×0.9，第 3 作 ×0.8……），逼玩家换题材。
- 作品名默认「原名 2」。

### 3.4 年度游戏大奖

- 每年 12 月第 4 周（待确认原作时间）举办，评选当年发售的所有作品（包括虚构的对手作品）。
- 奖项：年度最佳、最佳画面、最佳音乐、最佳创意、最差游戏（搞笑奖）。
- 获奖：奖金 + 粉丝；界面是一个逐项揭晓的弹窗（类似媒体评分的开奖动画）。
- 需要「对手作品」：每年生成若干虚构作品和分数，也能用在杂志的销量排行。

### 3.5 公司数据 / 纪录

- **公司数据**（信息 → 公司数据）：成立年数、累计作品、累计销量、累计收益、粉丝、最高分作品、历年收益表。
- **纪录**（标题画面）：名人堂（总分 ≥ 36 的作品，待定）、历代最高销量、最高分。跨存档保留，新游戏也不清空。

## 4. P2 功能

### 4.1 游戏展

- 每年 9 月（待确认）开展前一个月，杂志刊登招展通知，选展位：小（2,000 金）/ 中（5,000）/ 大（15,000）。
- 展期内粉丝按展位大小增加，正在开发的作品期待度大涨。
- 和杂志的事件框架对接：招展用一个 `ask` 事件实现。

### 4.2 办公室扩建

- 条件：资金和粉丝达标，花钱扩建。场景换成第二、第三个办公室，座位 4 → 6 → 8。
- 美术见 ASSETS.md「下一批：第二、三个办公室」。

### 4.3 渠道兴衰、签约、自建渠道

本作的主机换成了国内渠道，原作的「取得授权」和「主机寿命」要重新设计：

- **签约**（行动 → 取得授权 改名为「渠道签约」）：首次在某渠道发售前要付签约费，以后免费。现在是每次付上架费，二选一，要定。
- **渠道兴衰**：渠道的市场占比随年份变化（现在已经有 `share` 两端插值），可以做成杂志新闻：「XX 渠道用户突破一亿」「XX 平台宣布关停」。
- **自建渠道**：后期花大钱（例如 50 万）+ 硬件工程师，开自家渠道，分成 100%，用户量随自家作品数量和粉丝增长。

### 4.4 20 年结局

- 第 20 年 3 月底弹出总评：公司名、累计销量、最佳作品、名人堂数量、一个称号。
- 结局后可以继续玩，但不再计入纪录（原作做法，待确认）。

## 5. 需要你定的问题

1. 渠道费用：保留「每次上架费」，还是改成「首次签约费」？
2. 员工上限：现在 4 人。扩建前要不要允许超过 4 人（有人没座位）？原作是座位多少就多少人。
3. 名人堂门槛：总分 36 还是 40（原作满分 40）？
4. 对手作品：年度大奖和销量排行都需要虚构竞品，要不要做？做的话名字也走谐音路线。
5. 先做哪几个？建议按 P0 顺序：标题画面 + 命名 → 委托开发 → 招聘。

- 年度大奖：奖杯图标、颁奖弹窗。
- 扩建：第二、三个办公室的地板、墙、家具。
