# 开发物语 · 策划案：新企划流程

> 范围：右下「菜单」→ 开发 → 新企划，到项目正式开工为止的三个界面。
> 开发中、评分、销售只写和本流程有关联的部分（费用、渠道分成、方针对评分的影响）。
> 数值都是**初版**，先让原型跑起来再调。

---

## 0. 流程总览

```
菜单 → 开发 → 新企划
  │
  ├─ 界面① 新企划书 ─────────── 开发费用（自动合计）
  │     ├─ 渠道   → 渠道选择列表
  │     ├─ 类型   → 类型选择列表
  │     ├─ 内容   → 内容选择列表
  │     └─ 开发方针 → 开发方针选择列表
  │   [确定]
  ├─ 界面② 此次游戏的方针 ───── 8 项滑条分配方针点数（参考截图：方针页）
  │   [确定]
  ├─ 秘书：「这次让谁来当制作人？」
  ├─ 界面③ 制作人选择 ──────── 员工卡片左右翻页（参考截图：企划负责人 1/3）
  │   [确定]
  └─ 扣费 → 秘书：「《XX》开始开发了！」→ 进入开发中
```

和现有原型的差别：

| 项 | 原型现状 | 本案 |
|---|---|---|
| 第一行 | 主机（电脑 / 星环 SX / 口袋机 PK） | **渠道**（国内发行渠道，分成各不相同） |
| 第四行「方针」 | 点开是 8 项滑条 | 改为**开发方针**（普通 / 质量优先 / 速度优先 / 增加预算），各有价格 |
| 8 项滑条 | 从第四行进入 | 改成点「确定」后的**第二个界面** |
| 负责人 | 秘书问「谁写企划」→ 文字列表 | 秘书问「谁当制作人」→ **员工卡片翻页** |
| 开发费用 | 固定 500 | 按 类型 + 内容 + 开发方针 + 渠道 自动计算 |

返回逻辑：② 按「返回」回到 ①（已填的保留）；③ 按「返回」回到 ②；① 按「返回」放弃企划。

```
┌──────────── 新企划书 ────────────┐
│ 开发费用                  1,200金 │   ← 随选择实时刷新；钱不够时数字变红
│ ┌───────┬──────────────────────┐ │
│ │ 渠道  │ [图标] 自家官网       │ │
│ │ 类型  │ [图标] 桌上游戏  初   │ │
│ │ 内容  │ [图标] 寻宝      初   │ │
│ │开发方针│ 普通开发             │ │
│ └───────┴──────────────────────┘ │
│  🧍🧍🧍🧍  （员工小人一排）        │
│                         [确定]   │
└──────────────────────────────────┘
```

**开发费用** = （类型费 + 内容费）× 开发方针倍率 + 渠道上架费

开局 5,000 金，月薪合计约 250 金，第一作（如「桌上游戏 × 寻宝 × 普通 × 自家官网」）= 300 金，留足犯错空间。

钱不够时点「确定」：秘书「资金不够开发费用了……」，停在本界面。

### 1.1 渠道（替代原作「主机」）

原作的主机 = 平台授权费 + 市场占比。我们改成国内发行渠道：**上架费、分成、用户规模、偏好、准入门槛**各不相同。小公司前期只能上门槛低、分成低或用户少的渠道，做出名气后才能进大渠道。

> 名称先用谐音/化名，避免直接用真实商标。右侧「原型」只给策划和美术参考，不出现在游戏里。

| id | 游戏内名称 | 原型 | 上架费 | 开发者分成 | 市场占比 1年 → 3年 | 偏好（销量加成） | 审核 | 解锁条件 |
|---|---|---|---|---|---|---|---|---|
| web | 自家官网 | 官网 / 独立发行 | 0 | 100% | 3% → 2% | 无；靠粉丝自来水 | 0 周 | 开局 |
| h5 | 嘿嘿小游戏站 | 4399 类网页站 | 0 | 50% | 12% → 8% | 解谜、桌上、放置 +20% | 1 周 | 开局 |
| wx | 微讯小游戏 | 微信小游戏 | 300 | 60% | 25% → 28% | 亲和度高的作品 +20% | 2 周 | 开局 |
| tap | 塔塔社区 | TapTap | 200 | 85% | 10% → 14% | 创新评分高的作品 +30% | 2 周 | 发售过 1 部作品 |
| steam | 蒸汽平台 | Steam | 100 | 70% | 8% → 10% | 资深度高；动作、角色扮演、策略 +20% | 1 周 | 第 2 年 |
| hw | 华光应用市场 | 华为 / 硬核联盟 | 1,000 | 50% | 20% → 18% | 角色扮演、卡牌 +20% | 4 周 | 粉丝 ≥ 2,000 |
| qe | 企鹅游戏 | 腾讯 | 3,000 | 30% | 30% → 32% | 大众向（亲和度）+20% | 6 周 | 粉丝 ≥ 10,000 |

规则：

- **市场占比**决定这个渠道的潜在用户盘子，按年份在表中两值之间线性变化（以后可以做随机事件，比如「微讯小游戏大推广，占比 +5%」）。
- **分成**作用于收入：每份收入 = 单价 × 分成。
- **审核**：开发完成后要等 N 周才能发售，期间秘书提示「正在审核中」。
- **未解锁**的渠道在列表里显示为灰色，副标题写解锁条件（例：「粉丝 2,000 后可签约」）。

列表每行显示：名称、分成、市场占比；副标题：上架费 / 解锁条件。

### 1.4 相性（类型 × 内容，隐藏数值）

原作的核心乐趣之一：玩家自己摸索哪些组合好卖。相性不在企划书上显示，发售后在评语和「作品记录」里透露。

| 相性 | 评分修正 | 判定 |
|---|---|---|
| 绝配 | +20% | 下表指定 |
| 良好 | +8% | 类型与内容的喜好方针有 1 项重合，或下表指定 |
| 一般 | 0 | 其余 |
| 不搭 | −15% | 下表指定，或内容喜好 = 类型忌讳 |

指定组合（初版，后续补充）：

- 绝配：冒险×寻宝、模拟经营×料理、角色扮演×修仙、策略×三国、音乐节奏×偶像、冒险×侦探、放置×萌宠、射击×太空、动作×武侠、教育×校园
- 良好：动作×机器人、桌上游戏×萌宠、卡牌×三国、模拟经营×校园、射击×末日
- 不搭：教育×末日、桌上游戏×末日、音乐节奏×三国、解谜×武侠

| id | 名称 | 费用倍率 | 开发周数 | 点数产出 | Bug 产生 | 解锁 |
|---|---|---|---|---|---|---|
| normal | 普通开发 | ×1.0 | ×1.0 | ×1.0 | ×1.0 | 开局 |
| speed | 速度优先 | ×0.8 | ×0.7 | ×0.85 | ×1.4 | 开局 |
| quality | 质量优先 | ×1.3 | ×1.3 | ×1.2 | ×0.7 | 开局 |

## 2. 界面② 此次游戏的方针

参考截图（方针页）：标题「此次游戏的方针」，「剩余方针点数 N」，8 项两列，每项 10 格，选中项两侧黄色箭头；底部显示类型、内容图标 + 等级，右侧「确定」。底栏「帮助 / 返回」。

### 2.1 方针点数

**总点数 = 10 + 类型等级 + 内容等级**

开局 Lv1 + Lv1 = 12 点（和原作截图一致：已分配 10、剩余 2）。可以不用完。

### 2.2 方针的作用

**① 匹配度 → 评分修正**

```
喜好分 = 类型喜好 2 项 + 内容喜好 2 项 的点数之和（重复项算两次）
忌讳分 = 类型忌讳 1 项的点数
匹配度 = (喜好分 − 忌讳分 × 1.5) / 总点数         范围约 −1 ~ +2
评分修正 = clamp(匹配度 × 12%, −15%, +20%)
```

**② 方向 → 四项点数侧重**（每 1 点的效果）

| 方向 | 趣味 | 创新 | 画面 | 声音 | 其他 |
|---|---|---|---|---|---|
| 可爱度 | +1% | | +3% | | |
| 真实性 | | | +2% | +2% | |
| 亲和度 | +3% | | | | 大众向渠道销量 +2% |
| 资深度 | +2% | +2% | | | 粉丝增长 +2% |
| 操作性 | +3% | | | | Bug +1% |
| 新颖度 | | +4% | | | |
| 世界观 | | +2% | | +2% | |
| 精细度 | +1% | +1% | +1% | +1% | 周数 +2%、Bug −3% |

**③ 特色**：任意一项 ≥ 8 点，作品获得「特色」标签，创新 +10%，评语里会提到。鼓励偏科。

### 2.3 玩家怎么知道偏好

- 不直接告诉玩家。发售后评审评语会透露（原型已有：「玩家似乎很在意 X 和 Y」）。
- 透露过的偏好记入公司知识。之后在方针页，该方向名称旁显示小星标 ★（喜好）或 ✕（忌讳）。
- 「帮助」：秘书解释规则，并说一句已知的提示（「桌上游戏的玩家好像很重视亲和度。」）；还不知道就说「先做一部试试看吧」。

- 左右箭头翻页，按**编剧**从高到低排序。

**制作人的作用**

| 项 | 效果 |
|---|---|
| 开工加成 | 立即：趣味 + 编剧×2、创新 + 编剧×1.5（原型已有，沿用） |
| 擅长类型 | 每个员工有 1 个擅长类型（入职时随机）。制作人擅长本作类型 → 全程点数 +15%，开工时秘书提示「这正是他擅长的类型！」 |
| 体力 | 担任制作人体力 −30% |
| 作品记录 | 记录制作人姓名，以后可做「名制作人」称号 |

后续的画面负责人（40%）、声音负责人（75%）也改用这个卡片界面，排序分别按画面、作曲。

## 4. 开工后的关联数值

### 4.1 开发周期

```
目标周数 = 类型基础周数 × 开发方针周数倍率 × (1 + 精细度点数 × 2%)
每周进度 = 100 / 目标周数 × (团队编程合计 / 基准编程)     基准编程 = 60
```

开局 4 人团队编程合计约 60，做桌上游戏约 8 周（2 个月）出一作。

### 4.2 点数产出

```
每周每人点数 = 原型现有公式
            × 开发方针点数倍率
            × (1 + 类型等级加成 + 内容等级加成)
            × (1 + 方针方向侧重)
            × (制作人擅长 ? 1.15 : 1)
```

### 4.3 评分

```
综合分 = 原型现有公式 × (1 + 方针评分修正) × (1 + 相性修正)
```

### 4.4 销量与收入

```
每周销量 = 评分曲线 × (粉丝 × 0.3 + 渠道市场占比 × 渠道基数) × 渠道偏好加成 × 0.85^已售周数
每周收入 = 每周销量 × 单价 × 渠道分成
渠道基数 = 20,000（初版，调到第一作能小赚即可）
```

首作对比示例（同一作品）：自家官网 3% 用户、拿 100%；微讯小游戏 25% 用户、拿 60%，扣上架费 300 后仍是后者更赚——前提是作品够「亲和」。让玩家自己算这笔账。
