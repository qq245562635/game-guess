# 开发物语 · 场景一（初始办公室）出图需求 — 给 Codex

风格以 Codex 第一版效果图为准：毛毡 / 纸感手作风，暖色，非像素。
这一版效果图整体方向通过，下面是**拆成游戏素材**的规格，以及效果图需要调整的地方。
UI 部分见 `UI需求.md`。

## 场景构成（和原作一致）

- 老板一张桌（老板坐着，面朝镜头）
- 秘书一张前台（秘书坐着，面朝镜头，靠近门口）
- 员工 4 人岛式工位：2×2 拼桌，后排 2 人面朝镜头，前排 2 人背对镜头
- 装饰：白板、书架 ×2、饮水机、盆栽 ×2、地毯、门口脚垫
- 以后办公室扩建时再加座位，这一版**只画 4 个工位**

程序里的占位图已经按这个布局摆好了，截图见 `docs/ui/01-主界面.png`，Codex 可以对照它的位置来画。

## 对效果图的调整意见

1. **严格按 2:1 等角网格画**：1 格 = 128×64 的菱形。效果图的墙和桌子比 2:1 陡，拆开后会和地板对不上。
2. **桌面上方留出空间**：员工头顶会冒「趣味 +3」之类的气泡，要能看清。
3. **房间不要堆满**：书架、绿植往墙边收，中间走道留出来。
4. **加上老板桌和秘书前台**：效果图里没有这两个。
5. **人物分正面和背面两套**：后排员工、老板、秘书用正面，前排员工用背面。

## 通用规则

- 交付透明 PNG，**按表中尺寸的 2 倍出图**。
- 「锚点」是图内坐标（1x 尺寸下），这个点落在所在地块中心的地面上。物体底部中心对准它。
- 文件名 = key。
- 接入方式：放进 `games/kaifa-wuyu/assets/`，并把 key 列表写进 `assets/index.json`（例如 `["desk","chair"]`），游戏启动时自动替换占位图。

| key | 1x 尺寸 | 交付 | 说明 |

| bg_city | 1024×1664 | 2048×3328，不透明 | 房间**后面**的一整张图：上方天空、太阳、远山、远处房屋和树；房间两侧和下方的街道、人行道、斑马线、树丛、房屋 |

对齐规则（最重要）：

- 图内坐标 **(480, 704)**（1x）= 办公室地板的**后角**（两面墙交汇处的地面点）。房间就画在这个点下方：地板菱形四角在 (480,704)、(928,928)、(544,1120)、(96,896)，墙高 168。参考图里已经画出轮廓。
- 房间区域会被游戏盖住，这里画什么都行，建议画成地面颜色，免得边缘漏色。
- 房间**前两条边是开口**（参考图红线）：外面要和地板边缘自然衔接，像效果图那样有一圈人行道 / 矮墙 / 草地。
- 手机上实际能看到的范围：横向 x 90–934，纵向在 y 83–1523 之间（不同屏幕高度不同，参考图红框 / 蓝框）。框外是安全余量，玩家拖动镜头时会露出来，也要画完整，别留空白。
- 等角视角和地块方向与房间一致（2:1，光源左上），街道、房屋都按同一套等角网格画。
- 风格照 `ui-main-v2.png` 和已交付素材（毛毡 / 纸感 / 手作）。

**地面必须严格落在等角网格上（v1 返工点，v2 已通过）**：v1 的人行道、树篱、路缘和马路不是 2:1，左前边比网格陡、右前边比网格平，跟房间地板边缘对不上，游戏里看起来地板翘起来了。对照图：`art/previews/bg_city-v1-grid-check.png`（白线=网格，红线=房间前缘）。

- 底稿用 `art/reference/bg_city-ground-grid.png`：与交付图同尺寸，画好了网格、房间地板、紧贴房间前两边的 1 格人行道、0.5 格树篱、3 格马路。**所有地面上的直线（路缘、人行道边、树篱边、马路边、斑马线方向）都必须沿网格线**，斜率严格是 1:2（横走 2 像素、竖走 1 像素）。
- 人行道直接从红线开始，紧贴地板前缘，中间不要有楔形空隙，也不要让树篱压进红线以内。
- 只返工地面部分即可；天空、远山、远处房屋可以保留 v1。房屋和车的底边同样要贴网格。
- 自检：把网格底稿以 50% 透明度叠在成品上，所有路缘线都应该和网格线重合。

验收：放进 `assets/` 后用 HTTP 打开游戏，房间地板前缘要正好接上外面的人行道，左右屏幕边缘、顶栏下方、信息栏上方都不能露出灰底。
