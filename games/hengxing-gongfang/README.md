# 恒星工坊（暂定名）· 初版

按《恒星工坊》策划案做的第一个可玩版本：玩法对标戴森球计划的前两个阶段（着陆 → 自动化），极简几何画风，所有图形由代码绘制，没有任何外部图片和音频。

## 运行

- **网页**：浏览器直接打开 `index.html`（GitHub Pages 上就是这个文件）。电脑上会居中显示成手机宽度。
- **微信小游戏**：微信开发者工具 → 导入项目 → 选 `minigame/`，AppID 选测试号。详见 [minigame/README.md](minigame/README.md)。
- **改代码后**：`python3 tools/build.py` 重新生成上面两份；`node tools/sim.js` 跑模拟测试。

## 这一版做了什么

对照策划案「MVP 范围」：

| 策划案 MVP | 初版 |
|---|---|
| 一颗星球 256×256 格 | ✅ 种子生成；出生点四种基础矿各一片（6–11 格内），全图另有约 90 片矿脉，矿有储量会采完 |
| 采矿、传送带两级、分拣器、熔炉、组装机 | ✅ 另有分拣器两级、储物箱 |
| 风机与火电、电网 | ✅ 电线杆连成电网，供不应求时整网同比降速 |
| 约 25 种物品、约 20 个科技节点 | 23 种物品、16 个科技（2 个手动 + 14 个矩阵） |
| 产能面板、离线收益、本地与云存档 | 产能面板 ✅、离线收益 ✅、本地存档 ✅；云存档没做 |
| 主角机甲、4 架建造无人机、蓝图虚影施工 | ✅ 含排队序号、施工范围、范围外变灰、拆除返还 |
| 新手引导、目标卡片 | ✅ 14 步互动引导：高亮要点的按钮、地图上闪烁「放这里」，卡住时说明原因并指到具体建筑 |

### 核心循环

开局背包里有两条产线的建筑。采矿机放上铁矿 → 风机 + 电线杆通电 → 传送带运矿 → 熔炉 → 分拣器送料 → 储物箱装铁板 → 取出到背包 → 照样搭一条铜板线 → 研究「自动化组装」→ 组装机做齿轮 → 研究「电磁学」→ 组装机做初阶矩阵 → 科研站研究矩阵科技（火电、高速带、无人机、机甲……）。点矿脉让机甲手动采矿一直可用，但不是必经步骤。

### 新手引导（v2，按试玩反馈重做）

第一版引导一上来让人放风机和熔炉，没说为什么，也没指位置，试玩反馈「玩不懂」。现在：

- 14 步，一步只教一件事：先说为什么（「采矿机要用电才会动」），再说点哪里。
- 要点的快捷栏格子 / 底栏按钮闪黄框；地图上要放的位置闪烁并标「放这里」，镜头自动移过去。推荐位置以出生点最近的一块整 2×2 铁矿为原点排成一条线，机甲出生在线的中间。
- 蓝图迟迟不开工时说明原因：范围外（点蓝图机甲就飞过去）、背包没有且材料不够手搓（指向有缺料的储物箱让你「取出」）。研究、手搓缺材料时同样指到具体建筑。
- 第 3 步起只要有电网缺电，先提示在那张电网的电线杆旁边补风机。
- 研究「自动化组装」「电磁学」分别送 1 台组装机、1 座科研站，引导里不用绕去烧石砖。
- 用「只按提示操作」的机器人在随机地图上从头玩来验证（见下面测试）。

### 规则要点

- **配方**（`src/data.js` 一张表）：铁矿/铜矿/石料 → 熔炉 → 铁板/铜板/石砖；组装机做齿轮、线圈、电路板、初阶矩阵和全部建筑。配方保留「多输入」结构，线圈一次出 2 个、石砖要 2 个石料，产能要算。
- **传送带**：普通 6 个/秒，高速 12 个/秒；物品逐个可见。拖线自动走 L 形并生成弯道；侧面接入就是汇流。
- **分拣器**：从身后抓、往身前放，可设过滤。放在传送带和建筑之间会自动朝向（送料或出料）。
- **采矿机** 2×2：按覆盖的矿格数出矿（每格 0.25/秒，满 4 格 = 1/秒，刚好喂饱一台熔炉）；出口朝箭头方向，直接吐到正前方的传送带上。
- **熔炉**：送什么矿就炼什么（第一次送进来的矿决定配方），也可以手选。组装机要手选配方。
- **电网**：电线杆覆盖半径 4.5 格、连接距离 10 格。风机 400 kW；火电站 2160 kW、烧煤。用电超过发电时，整个电网的建筑同比降速（不随机停机）。
- **机甲**：点空地飞过去，点矿脉采矿（0.8 秒一个）；有能量条，在电网覆盖区里快速回能，在外面慢慢回能（不会卡死）。
- **建造无人机**：放下的建筑只是蓝图，4 架无人机按放置顺序飞去施工，只施工机甲 14 格内的蓝图。背包里没有该建筑时，机甲会自动手搓（缺的齿轮、电路板等中间件一起做，甚至从矿石手工冶炼）。
- **科技**：前三个科技直接花背包物品；之后的靠科研站消耗初阶矩阵，可中途切换（进度保留）。
- **离线**：按存档前 60 秒「进储物箱的净速率」和研究速率结算，最多 8 小时；储物箱满了就停。

## 操作

浏览和建造分两个模式，避免误触；常用操作都在下半屏，点击目标 ≥ 44×44。

| | 浏览模式 | 建造模式 |
|---|---|---|
| 单指拖动 | 平移地图 | 拉传送带（L 形）/ 连续放置 |
| 双指 | 缩放、平移 | 缩放、平移 |
| 单击 | 建筑 → 详情；矿 → 采矿；空地 → 机甲飞过去 | 放蓝图；点已有的带 → 转向 |
| 长按 | 框选（拆除） | 旋转（传送带除外） |
| 底栏 | 背包 · 科技 · 产能 · 建筑 · 拆除；8 格快捷建造 | 旋转 · 拐角（自动/先横/先竖）· 完成 |

电脑上：滚轮缩放，右键拖动平移，`R` 旋转，`Esc` 退出，`1`–`8` 选建筑，`X` 拆除模式，`B`/`T`/`P` 背包/科技/产能，`WASD` 平移。

## 画面

深色底 + 类别色描边 + 几何图标：青色采集、橙色加工、紫色科研、黄色电力、钢蓝物流。物品靠形状区分（矿石圆、板材方、零件六边形、矩阵菱形），色弱也能分辨。传送带等级只换箭头颜色。拉远时不画单个物品，传送带直接按承载物品着色；再远只画色块。产能面板点一行，地图上产出该物品的建筑亮绿框、消耗的亮红框。

## 技术

和策划案的分层一致：

- **模拟层** `src/core.js` + `src/data.js`：全部规则，纯 JS，不碰渲染和平台 API，Node 里能直接跑（`tools/sim.js`）。固定每秒 15 tick，表现层在 tick 之间插值。
- **表现层** `src/gl.js`（WebGL1 渲染器，一个 SDF 着色器画圆角矩形、胶囊、圆弧、六边形、图集贴图、地面贴图）、`src/icons.js`（建筑和界面图标，启动后用 2D 画布画进图集）、`src/view.js`（世界）、`src/ui.js`（界面，全部画在画布里）、`src/input.js`。锁 30fps。
- **平台层** `src/platform.web.js` / `src/platform.wx.js`：画布、触摸、存档、音效、震动、切后台存档、分享。
- **构建** `tools/build.py`：同时产出 `index.html` 和 `minigame/`，并检查小游戏包里没有 `document`/`window`/`localStorage` 等浏览器对象，也没有老引擎不认的 `?.` `??` `{...}`。

### 测试与实测数据

`node tools/sim.js`（全部通过）：

- 产线：采矿机 → 6 格带 → 分拣器 → 熔炉 → 分拣器 → 储物箱，3 台风机供电，120 秒进箱 108 块铁板（理论 1/秒）；只有 1 台风机时满足率 0.56，进箱 61 块（同比降速）
- 无人机：范围内 5 个蓝图 6 秒建完；范围外排队，机甲靠近后自动开工；拆除时建筑和带上物品回背包
- 手搓：只有铁板铜板也能排「采矿机」（自动排齿轮 → 线圈 → 电路板 → 采矿机）；放了蓝图但背包没有 → 自动手搓再施工；背包已有铜板时点手搓铜板真的会多做一个（第一版误判「已经有了」什么都没做），缺矿时说出缺什么
- 科研：手动科技扣物品；科研站 20 矩阵 × 3 秒完成「无人机扩编」
- 存档往返 + 离线 1 小时结算；小工厂存档约 1 KB
- 引导目标计数在真实产线上能推进

**引导验证**：写了一个只按提示操作的机器人（只点高亮的按钮 / 闪烁的格子，面板里只按提示文字点名的按钮，用真实的点击和拖动），在 8 张随机地图上从开局玩到引导结束，全部走完 14 步，每局约 100 个操作。铜板线在不同地图上会朝东、南、西不同方向排，都能走通。第一轮试跑时它在第 8、10、11、12、13 步各卡过一次，都是真玩家也会卡的地方（蓝图在范围外、背包缺料却只显示「施工中」、建造模式下看不到「科技」按钮、科研站要石砖、引导位置旁边没有铜矿、放置朝向不对），已逐个修掉。

浏览器（Chromium 无头，390×844 @2x）按真实点击和拖动走了一遍：开始 → 采矿 → 放风机/熔炉/电线杆 → 无人机施工 → 拉 L 形传送带 → 各面板 → 存档刷新后继续。另外把 `minigame/game.js` 放进 Worker（没有 `document`/`window`/`localStorage`）里，用假的 `wx` + OffscreenCanvas WebGL 跑：开始、采矿、双指缩放、建造、切后台存档都正常，顶部栏避开了右上角胶囊按钮。

性能（这台开发机，不是手机）：

| 场景 | 结果 |
|---|---|
| 9840 个物品在带上跑 + 11840 栋建筑 | 单 tick 约 4.3 ms |
| 屏幕上约 2800 个物品、700 栋建筑 | 每帧 JS 约 1.5–3 ms，1 次 draw call |
| 包体 | 小游戏约 114 KB（预算 2 MB） |

**还没在真机上测。** 中端安卓的 JS 一般比这台机器慢 2–4 倍，1 万物品时单 tick 可能超过策划案的 8 ms 预算，这正是里程碑 1（技术验证）要先解决的。

## 和策划案还差什么

- **传送带「段 + 间隙」表示**：现在是每格一个物品数组（开销跟物品数成正比）。策划案要求开销与物品数无关，里程碑 1 改。
- **模拟层放 Worker 线程**：`core.js` 已经不依赖任何平台 API，搬过去是机械工作，等真机数据再做。
- **地面和静态建筑分块预渲染**：现在地面是一张 256×256 贴图，建筑每帧重画（已经 1 次 draw call）。
- **稳态区块速率模式**：离线结算用的是速率近似，在线还是逐个模拟。
- **存档二进制压缩、云存档**：现在是 JSON 存本地。
- **框选后复制 / 整体移动 / 蓝图库**：现在框选只能拆除。
- **传送带上下桥接、分流器**：没做，交叉要绕开。
- **抖音小游戏**：平台层 API 基本同名（`tt.*`），还没出工程。
- **TypeScript strict**：初版和仓库里其他游戏一样用纯 JS（不需要构建环境就能开），按策划案要切到 TS strict + lint。
- 数值（配方、功率、科技价格、引导节奏）是第一版拍的，等试玩后由策划调；全部在 `src/data.js`。
